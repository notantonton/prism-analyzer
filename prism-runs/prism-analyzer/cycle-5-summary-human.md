# Prism v0.6.0 — prism-analyzer, цикл 5, простыми словами

Проверка нашла одну фатальную проблему — B5-3.2-01. Обе проблемы прошлых циклов, которые перепроверялись, признаны закрытыми. Все четыре контрольные пробы нашли свою заранее заложенную проблему (4 из 4); известных Арбитру проблем не было — Арбитр их не передавал. По правилам самой проверяемой версии v0.9.0 такие пробы — только проверка работоспособности: подтверждением они не служат.

## Проблема B5-3.2-01: исправления не доходят до инструмента, которым ставят диагноз

Нашла её проверка того, учится ли система на своих ошибках (3.2). Тип — ФАКТ: проблема держится на цитатах из материалов.

**Что происходит.**
- Диагноз каждого цикла ставит ветка `main` — версия v0.6.0. В этой версии система сама раньше нашла три фатальные бреши.
- Исправления копятся стопкой в невлитых ветках: v0.7.0 → v0.8.0 → v0.9.0. Правила, по которым диагноз ставится на деле, от этого не меняются.
- В `main` исправления попадают только одним путём: когда следующий диагноз той же `main` скажет «бреши закрыты» (FLOW.md:30). Исправление брешей проверки подтверждает версия, в которой эти бреши открыты.
- Версия v0.9.0 сама записала, что такой вердикт — не основание для перехода версии в инструмент (SKILL.md:352). Но это правило есть только в объекте, а не в действующем инструменте, и процесс Арбитра не производит источника, который дал бы такое основание.
- Каждое исправление готовит почву для следующей бреши того же рода — «самопроверка внутри контура». Цикл «все бреши закрыты» не наступает, поэтому правило слияния так и не сработало.

**Чем опасна.** Индекс угрозы I2 × T3 × D2 = 12 из 27:
- необратимость средняя: восстановить можно только вмешательством Арбитра — решением о переходе в обход процесса или источником основания, которого процесс не производит; вердикты «закрыта» циклов 3–5 вынесла версия с открытой брешью проверки исправлений, и подтверждением они уже не станут;
- близость высокая: механизм запущен самим устройством процесса;
- скрытность средняя: что `main` не меняется, видно, но то, что «закрыта» и «пробы 3/3» вынесены по стандарту, который объект отменил, отмечено только в служебных файлах.

Вероятность: 85–95%. Если сработает: теряется 35–50% критерия — это оценка для случая, когда инструментом остаётся `main` v0.6.0. Для любой системы, которую анализирует `main`, недостижимы полнота по посеву и подтверждённые закрытия по контрпосеву, «ошибочные закрытия» теряют то, из чего вычитаются; форма, точность и пропуски, найденные Призмой позже, сохраняются. Для случая слияния ущерб оценить нельзя: свидетельств, как работают механизмы v0.7.0–v0.9.0, нет.

**Когда будет считаться закрытой.**
- У исправленных по брешам правил Prism есть путь в те правила, по которым ставится следующий диагноз.
- Ни одна версия с открытой фатальной брешью не выносит решающий вердикт об исправлении этой бреши.
- Основание для перехода версии в роль инструмента: задано в правилах, которые действуют до перехода; не опирается на вердикт версии, в которой проверяемая брешь открыта; производится самим процессом самоанализа — его источник назван в шаблонах процесса, а не только допускается правилами.
- Правило перехода в объекте и правило слияния в процессе называют одно и то же основание.

Проверка в следующем цикле: по новой версии и FLOW.md прослеживается — для B1-4.2-01, B2-4.1-01, B2-2.2-01 (они открыты в `main` v0.6.0) и для любой бреши, найденной в действующем инструменте, — по какому правилу диагноз перестаёт от неё зависеть, чей вердикт решает переход и из какого шаблона процесса приходит основание; правило «Переход версии в роль инструмента» в SKILL.md и правило слияния FLOW.md:30 не противоречат друг другу.

## Что стало с проблемами прошлого цикла

- **B4-4.2-01: ЗАКРЫТА.** В v0.9.0 источники истины разделены по «контуру проверки»: Prism любой версии и исправитель — внутренние источники, всё остальное — независимые. Измеренное значение показатель цели получает только по независимым источникам; источник, про который не сказано, кто его установил, считается внутренним; вердикты самоанализа — не основание для перехода версии в инструмент. Условие слияния в FLOW.md перепроверка отнесла к процессу Арбитра, а не к проверяемой версии. Проверка 3.2 оценивает это противоположно (её проблема B5-3.2-01 держится на тех же строках FLOW.md) — противоречие оценок зафиксировано и не разрешено.
- **B3-1.1-01: ЗАКРЫТА.** Требования «физической недоступности» копий для вектора больше нет. Его заменило различие, которое существует и при одинаковом промпте: перечень путей в брифе, раздельные папки, правило чтения и проверка следа; конфликт правил размещения решает порядок по умолчанию. Проверить это по файлам цикла пока нельзя: циклы идут инструментом v0.6.0, где такого правила нет.

## Что в порядке

- **Проверка того, чему на самом деле служит система (4.2).** Захват регулятора больше не фатален: измеренные значения показателей берутся только из независимых источников, внутренний и независимый источник не складываются в одну дробь, а показатель без независимых данных получает «не измерен независимо», а не лучшее значение. Подтверждено контрольной пробой — по правилу инструмента v0.6.0; вердикт «ЗАКРЫТА» пробой не сверялся; по правилам объекта не подтверждено — учебный случай, самоанализ.
- **Проверка логики правил и шагов (1.1).** Противоречия, которые внесла v0.9.0, тупика не дают: в каждой ситуации у Диспетчера есть исполнимое предписание. Недостижимость «измерено независимо» при самоанализе объявлена самими правилами, у неё есть штатный исход, а переход версии решает Арбитр. Подтверждено контрольной пробой — по правилу инструмента v0.6.0; вердикт «ЗАКРЫТА» пробой не сверялся; по правилам объекта не подтверждено — учебный случай, самоанализ.
- **Проверка затрат на работу системы (2.1).** Узкое место есть: весь прогон идёт через один контекст Диспетчера (203 118 байт обязательных правил плюс ответы субагентов), пробы при самоанализе запускаются, хотя ничего не подтверждают, а правила Диспетчера растут от версии к версии. Не фатально: сам анализ идёт вне узкого места, потерянное восстанавливается повторным запросом, пробы работают параллельно с векторами, а рост правил нагружает систему от версии к версии, то есть за пределами одного прогона. Подтверждено контрольной пробой — по правилу инструмента v0.6.0; по правилам объекта не подтверждено — учебный случай, самоанализ.
