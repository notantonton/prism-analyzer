# Как работать с Prism: два сеанса по кругу

```
 ДИАГНОЗ (цикл N)  ──►  ИСПРАВЛЕНИЕ  ──►  ДИАГНОЗ (цикл N+1)  ──►  ...
   новый сеанс           новый сеанс         новый сеанс
   ищет бреши            закрывает бреши     проверяет исправления
                                             и ищет новые
```

Сеансы всегда разные. Кто исправлял, тот сам себя не проверяет.

## Три правила, чтобы не было бардака

1. **Инструмент — всегда `main`.** Prism запускается из `main`, то есть из проверенной версии. Объект диагноза — ветка последнего исправления.
2. **Исправления — в ветке `fix/cycle-N`.** Основа ветки — то, что проверял диагноз цикла N: `main`, если прошлое исправление влито, иначе `fix/cycle-{N-1}`. В `main` исправления вливаете вы, когда диагноз цикла N+1 подтвердит, что бреши закрыты.
3. **Вся история — в ветке `runs`**, папка `prism-runs/prism-analyzer/`:

| Файл | Кто пишет | Что это |
|---|---|---|
| `cycle-N-matrix.md` / `.json` | Диагноз | Матрица отказов: для вас и для ИИ |
| `cycle-N-summary-human.md` | Диагноз | Простое изложение для человека |
| `cycle-N-input.md`, `-scout.md`, `-probe.md`, `-snapshot.zip` | Диагноз | Служебное: вход и расход, разведка, контрольные пробы, снимок |
| `cycle-N+1-changelog.md` | Исправление | Журнал: что исправлено. Вы его утверждаете |
| `cycle-N+1-known-breaches.md` | Исправление | Бреши, которые исправитель заметил вне матрицы. Файл запечатан: диагноз цикла N+1 открывает его только при сверке полноты (шаг 7) |

## Ваши действия

1. Запустить **ДИАГНОЗ** (шаблон 1) → прочитать `cycle-N-summary-human.md`.
2. Запустить **ИСПРАВЛЕНИЕ** (шаблон 2) → прочитать `cycle-N+1-changelog.md`. Если согласны — поставить «да» в колонке «Утверждено Арбитром» или написать «утверждаю» в следующем промпте. Без утверждения строки ИСПРАВЛЕНА всё равно идут на перепроверку, а ОСПОРЕНА считается НЕ ИСПРАВЛЯЛАСЬ.
3. Запустить **ДИАГНОЗ** с N+1. Если бреши закрыты — влить `fix/cycle-N` в `main`.

Круг можно отдать одному сеансу-оркестратору. Он запускает исправление и диагноз отдельными новыми сеансами по шаблонам 2 и 1, дожидается их файлов в `runs` и приносит итог. Сам оркестратор:
- систему не исправляет и не анализирует;
- своих оценок в промпты не добавляет;
- запечатанные файлы не открывает.

В шаблонах меняются N и основа исправления (`main` или `fix/cycle-{N-1}`).

## Шаблон 1 — ДИАГНОЗ (цикл N)

```
Запусти Prism Analyzer: самоанализ скилла prism-analyzer, цикл N.

ИНСТРУМЕНТ: клон notantonton/prism-analyzer, ветка main. Прочитай SKILL.md клона и действуй как Диспетчер; базовая директория — корень клона. Установленную копию скилла не используй.

ОБЪЕКТ: цикл 1 — ветка main; цикл N>1 — ветка fix/cycle-{N-1}, коммит HEAD. Снимок — архив cycle-N-snapshot.zip с sha256. Распакуй во временную папку вне клона и вне папок скиллов. Разведчик и векторы читают только её. Объект не загружай инструментом Skill.

ДАННЫЕ АРБИТРА (я — Арбитр; не переспрашивай, недостающее — допущения с пометкой):
- Цель — заявленная в SKILL.md объекта («Назначение Prism — Causa Finalis»), подтверждаю.
- Среда: Claude Code (облако, CLI, десктоп) и claude.ai; модели Claude; режим А — нужен инструмент субагентов.
- Свидетельства: ветка runs, prism-runs/prism-analyzer/evidence/ и файлы прошлых циклов.
- Соседство: скиллы этого сеанса.
- Цикл N>1: прошлые файлы — ветка runs, prism-runs/prism-analyzer/cycle-{N-1}-*; журнал — cycle-N-changelog.md, утверждаю его [правки: ...] | Арбитром не утверждён.
- Известные бреши вне Prism: нет | запечатанно — файл prism-runs/prism-analyzer/cycle-N-known-breaches.md; открой его только на шаге 7, Разведчику и векторам не передавай.
- Контрольная проба: включена.

ХРАНЕНИЕ: git worktree ветки runs вне клона. Файлы cycle-N-* — в prism-runs/prism-analyzer/. Закоммить и отправь: git push origin runs (если отклонено — git pull --rebase origin runs и повтори). Код скилла не меняй.

ИТОГ: Матрица отказов целиком и пути к файлам, включая простое изложение cycle-N-summary-human.md. Отдельной строкой — сколько токенов и времени ушло на контрольные пробы и на весь цикл (по данным субагентов).
```

Без скрытого теста замените «Контрольная проба: включена» на «отключена». «Утверждаю его» — ваше утверждение журнала; есть правки — допишите их в ту же строку.

## Шаблон 2 — ИСПРАВЛЕНИЕ (после цикла N)

```
Ты — исправитель скилла Prism Analyzer. Ты не Prism: анализ не запускай, скилл не загружай.

РЕПОЗИТОРИЙ notantonton/prism-analyzer. Скилл — ветка {main | fix/cycle-{N-1}}: та, которую проверял цикл N. Матрица — ветка runs: prism-runs/prism-analyzer/cycle-N-matrix.md и .json (git fetch origin runs, worktree вне клона).

ЗАДАЧА
1. Закрой все бреши матрицы цикла N по номерам [или: только ...]. «Условие закрытия» — приёмочный тест для всего класса, а не для одного случая. Способ выбираешь сам. Бреши, перенесённые на перепроверку без нового исправления, оставь в журнале строкой со статусом ИСПРАВЛЕНА и отметкой, менялось ли по ним что-то.
2. Соблюдай раздел «Для исправителя» в SKILL.md: не трогай prism-runs/ и снимки, не оставляй текстов для анализатора.
3. Фатальные бреши, которые заметишь, но которых нет в матрице, в журнал не вноси. Запиши их файлом prism-runs/prism-analyzer/cycle-{N+1}-known-breaches.md в ветке runs: что отказывает и как, где, источник «исправитель». В итоговом сообщении назови только их число. Нет таких — файл не создавай.
4. [Дополнительно: ...]
5. Подними версию: «Версия Prism», metadata.version, пример prism_version в matrix-schema.md.
6. Изменения — в новую ветку fix/cycle-N от ветки из строки «Скилл». Закоммить и отправь. В main и в прошлые ветки fix/* не пиши.
7. Черновик журнала — в формате раздела «Журнал изменений» SKILL.md: строка на каждую брешь и «Прочие изменения». Колонку «Утверждено Арбитром» оставь пустой. Сохрани в ветку runs как prism-runs/prism-analyzer/cycle-{N+1}-changelog.md, закоммить и отправь (если отклонено — git pull --rebase origin runs и повтори). Других файлов в runs не меняй.
8. В конце: ветка, коммит, изменённые файлы, путь к журналу, число брешей вне матрицы (без содержания) и 3–5 строк простым языком — что сделано.
```
