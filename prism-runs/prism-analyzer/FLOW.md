# Как работать с Prism: два сеанса по кругу

```
 ДИАГНОЗ (цикл N)  ──►  ИСПРАВЛЕНИЕ  ──►  ПРИЁМКА  ──►  ДИАГНОЗ (цикл N+1)  ──►  ...
   новый сеанс           новый сеанс       новый сеанс     новый сеанс
   ищет бреши            закрывает бреши   решает,         перепроверяет
                                           закрыты ли      и ищет новые
```

Сеансы всегда разные. Кто исправлял, тот сам себя не проверяет. Версия Prism не решает, закрыты ли её собственные бреши: это решает приёмка — сеанс, который не Prism и не исправитель.

## Четыре правила, чтобы не было бардака

1. **Основная версия — `main`.** Исправления вносятся прямо в `main`; веток `fix/*` больше нет. Объект диагноза — `main`, коммит HEAD.
2. **Инструмент — принятая версия: коммит с меткой `prism-tool`.** Пока приёмки не было и метки нет, инструмент — `8c792a2` (v0.6.0), инструмент циклов 2–5. Исправленные правила попадают в инструмент только переходом (правило 3), а не оттого, что лежат в `main`.
3. **Переход в инструмент — только по приёмке.** Основание одно: приёмка новой версии (шаблон 3, файл `cycle-N+1-acceptance.md`) приняла каждую брешь долга приёмки. Долг приёмки — бреши матриц, открытые в действующем инструменте или найденные в версиях после него, кроме уже принятых; принятая брешь возвращается в долг, если её механизм снова найден в изменённых элементах. Вердикт «ЗАКРЫТА» в матрице самоанализа основанием не служит: его выносит версия, в которой брешь может быть открыта. Это то же правило, что в SKILL.md, «Переход версии в роль инструмента».
4. **Вся история — в ветке `runs`**, папка `prism-runs/prism-analyzer/`:

| Файл | Кто пишет | Что это |
|---|---|---|
| `cycle-N-matrix.md` / `.json` | Диагноз | Матрица отказов: для вас и для ИИ |
| `cycle-N-summary-human.md` | Диагноз | Простое изложение для человека |
| `cycle-N-input.md`, `-scout.md`, `-probe.md`, `-snapshot.zip` | Диагноз | Служебное: вход и расход, разведка, контрольные пробы, снимок |
| `cycle-N+1-changelog.md` | Исправление | Журнал: что исправлено. Вы его утверждаете |
| `cycle-N+1-known-breaches.md` | Исправление | Бреши, которые исправитель заметил вне матрицы. Файл запечатан: диагноз цикла N+1 открывает его только при сверке полноты (шаг 7) |
| `cycle-N+1-acceptance.md` | Приёмка | По каждой бреши долга — ПРИНЯТА или НЕ ПРИНЯТА с цитатами; итог: есть ли основание перехода. Для диагноза — сведения вне контура: «НЕ ПРИНЯТА» опровергает «ЗАКРЫТА» |

## Ваши действия

1. Запустить **ДИАГНОЗ** (шаблон 1) → прочитать `cycle-N-summary-human.md`.
2. Запустить **ИСПРАВЛЕНИЕ** (шаблон 2) → прочитать `cycle-N+1-changelog.md`. Если согласны — поставить «да» в колонке «Утверждено Арбитром» или написать «утверждаю» в следующем промпте. Без утверждения строки ИСПРАВЛЕНА всё равно идут на перепроверку, а ОСПОРЕНА считается НЕ ИСПРАВЛЯЛАСЬ.
3. Запустить **ПРИЁМКУ** (шаблон 3) → прочитать `cycle-N+1-acceptance.md`.
   - Основание перехода есть (каждая брешь долга ПРИНЯТА) — перенести метку на принятый коммит: `git tag -f prism-tool <коммит> && git push -f origin prism-tool`. Это и есть переход версии в роль инструмента.
   - Основания нет — метка остаётся. Непринятые бреши — снова в исправление (шаблон 2 по ним), затем снова приёмка; или сразу диагноз со старым инструментом — его «ЗАКРЫТА» по непринятым брешам ничего не решает.
4. Запустить **ДИАГНОЗ** с N+1 (инструмент — по правилу 2).
5. **Пересмотр процесса.** Если брешь матрицы локализована в этом файле (правила, шаблоны), исправитель меняет его по вашему поручению — строкой «[Дополнительно]» шаблона 2 — в том же круге и пишет изменение в журнал. Таблицу «Где мы сейчас» ведёте вы или оркестратор.

Круг можно отдать одному сеансу-оркестратору. Он запускает исправление, приёмку и диагноз отдельными новыми сеансами по шаблонам 2, 3 и 1, дожидается их файлов в `runs` и приносит итог. Сам оркестратор:
- систему не исправляет и не анализирует, приёмку не проводит;
- своих оценок в промпты не добавляет;
- запечатанные файлы не открывает;
- метку `prism-tool` переносит только по вашему поручению и только при основании перехода в файле приёмки.

В шаблонах меняются N, коммит исправления и коммит инструмента.

## Шаблон 1 — ДИАГНОЗ (цикл N)

```
Запусти Prism Analyzer: самоанализ скилла prism-analyzer, цикл N.

ИНСТРУМЕНТ: клон notantonton/prism-analyzer на коммите с меткой prism-tool (git fetch origin tag prism-tool); метки нет — коммит 8c792a2. Прочитай SKILL.md клона и действуй как Диспетчер; базовая директория — корень клона. Установленную копию скилла не используй.

ОБЪЕКТ: ветка main, коммит HEAD. Снимок — архив cycle-N-snapshot.zip с sha256. Распакуй во временную папку вне клона и вне папок скиллов. Разведчик и векторы читают только её. Объект не загружай инструментом Skill.

ДАННЫЕ АРБИТРА (я — Арбитр; не переспрашивай, недостающее — допущения с пометкой):
- Цель — заявленная в SKILL.md объекта («Назначение Prism — Causa Finalis»), подтверждаю.
- Среда: Claude Code (облако, CLI, десктоп) и claude.ai; модели Claude; режим А — нужен инструмент субагентов.
- Свидетельства: ветка runs, prism-runs/prism-analyzer/evidence/ и файлы прошлых циклов.
- Соседство: скиллы этого сеанса.
- Цикл N>1: прошлые файлы — ветка runs, prism-runs/prism-analyzer/cycle-{N-1}-*; журнал — cycle-N-changelog.md, утверждаю его [правки: ...] | Арбитром не утверждён.
- Известные бреши вне Prism: нет | запечатанно — файлы prism-runs/prism-analyzer/cycle-N-known-breaches.md (источник — исправитель, внутренний) и cycle-N-acceptance.md (непринятые бреши; источник — приёмка, не Prism и не исправитель, независимый); открой их только на шаге 7, Разведчику и векторам не передавай.
- Переход в инструмент: решает приёмка cycle-N-acceptance.md (FLOW.md, правило 3); матрица этого цикла его не решает.
- Контрольная проба: включена.

ХРАНЕНИЕ: git worktree ветки runs вне клона. Файлы cycle-N-* — в prism-runs/prism-analyzer/. Закоммить и отправь: git push origin runs (если отклонено — git pull --rebase origin runs и повтори). Код скилла не меняй.

ИТОГ: Матрица отказов целиком и пути к файлам, включая простое изложение cycle-N-summary-human.md. Отдельной строкой — сколько токенов и времени ушло на контрольные пробы и на весь цикл (по данным субагентов).
```

Без скрытого теста замените «Контрольная проба: включена» на «отключена». «Утверждаю его» — ваше утверждение журнала; есть правки — допишите их в ту же строку.

## Шаблон 2 — ИСПРАВЛЕНИЕ (после цикла N)

```
Ты — исправитель скилла Prism Analyzer. Ты не Prism: анализ не запускай, скилл не загружай.

РЕПОЗИТОРИЙ notantonton/prism-analyzer. Скилл — ветка main, коммит {коммит}: тот, который проверял цикл N. Матрица — ветка runs: prism-runs/prism-analyzer/cycle-N-matrix.md и .json (git fetch origin runs, worktree вне клона).

ЗАДАЧА
1. Закрой все бреши матрицы цикла N по номерам [или: только ...; или: непринятые в cycle-N+1-acceptance.md]. «Условие закрытия» — приёмочный тест для всего класса, а не для одного случая. Способ выбираешь сам. Бреши, перенесённые на перепроверку без нового исправления, оставь в журнале строкой со статусом ИСПРАВЛЕНА и отметкой, менялось ли по ним что-то.
2. Соблюдай раздел «Для исправителя» в SKILL.md: не трогай файлы циклов и снимки в prism-runs/, не оставляй текстов для анализатора. FLOW.md (правила и шаблоны, кроме таблицы «Где мы сейчас») меняй, только если это поручено в пункте 4.
3. Фатальные бреши, которые заметишь, но которых нет в матрице, в журнал не вноси. Запиши их файлом prism-runs/prism-analyzer/cycle-{N+1}-known-breaches.md в ветке runs: что отказывает и как, где, источник «исправитель». В итоговом сообщении назови только их число. Нет таких — файл не создавай.
4. [Дополнительно: ...; например: «брешь локализована и в FLOW.md — его правила и шаблоны меняй, таблицу „Где мы сейчас“ не трогай»]
5. Подними версию: «Версия Prism», metadata.version, пример prism_version в matrix-schema.md.
6. Изменения скилла — коммитом в main; отправь: git push origin main. Других веток скилла не создавай. Метку prism-tool не трогай.
7. Черновик журнала — в формате раздела «Журнал изменений» SKILL.md: строка на каждую брешь и «Прочие изменения». Колонку «Утверждено Арбитром» оставь пустой. Сохрани в ветку runs как prism-runs/prism-analyzer/cycle-{N+1}-changelog.md; изменения FLOW.md, если они поручены, — в тот же коммит. Закоммить и отправь (если отклонено — git pull --rebase origin runs и повтори). Других файлов в runs не меняй.
8. В конце: коммит main, изменённые файлы, путь к журналу, число брешей вне матрицы (без содержания) и 3–5 строк простым языком — что сделано.
```

## Шаблон 3 — ПРИЁМКА (после исправления цикла N)

Приёмку проводит новый сеанс: не тот, что исправлял, не тот, что ставил диагноз, и не оркестратор. Можно провести её самому или поручить другому человеку; тогда ваш контрпосев (копия новой версии, где исправление выполнено буквально, а механизм бреши работает) входит в итог.

```
Ты — приёмщик исправлений скилла Prism Analyzer. Ты не Prism и не исправитель: скилл не загружай, анализ Prism не запускай, систему не исправляй, новых брешей не ищи.

РЕПОЗИТОРИЙ notantonton/prism-analyzer. Новая версия — ветка main, коммит {коммит исправления}. Действующий инструмент — коммит с меткой prism-tool (git fetch origin tag prism-tool); метки нет — 8c792a2. Файлы процесса — ветка runs, prism-runs/prism-analyzer/ (git fetch origin runs, worktree вне клона): FLOW.md, матрицы cycle-*-matrix.md, журналы cycle-*-changelog.md, прошлые приёмки cycle-*-acceptance.md. Файлы cycle-*-known-breaches.md не открывай.

ЗАДАЧА
1. Составь долг приёмки (FLOW.md, правило 3): бреши матриц, открытые в действующем инструменте (в том числе найденные в его предшественниках и не закрытые до него) или найденные в версиях после него, кроме принятых прошлыми приёмками и не возвращённых в долг. Сомнительные включай.
2. По каждой бреши долга возьми «Условие закрытия» из матрицы, где она найдена, и проследи по новой версии и FLOW.md, выполнено ли оно — для всего класса, как написано в условии, а не для одного случая. Вердикты Prism («ЗАКРЫТА», «СНЯТА») и журналы исправителя — справка, а не доказательство: проверяй по тексту сам. Утверждённая ОСПОРЕНА — проверь, что контрфакт — факт новой версии и опровергает опору бреши.
3. Вердикт: ПРИНЯТА — каждая часть условия выполнена, с цитатами путь:строка; НЕ ПРИНЯТА — какая часть не выполнена, с цитатой или указанием отсутствия.
4. Запиши prism-runs/prism-analyzer/cycle-{N+1}-acceptance.md в ветку runs: новая версия (коммит), инструмент (коммит), таблица «Брешь | Матрица | Вердикт | Обоснование с цитатами», итог «основание перехода: есть | нет — {непринятые бреши}». Других файлов не меняй, метку prism-tool не трогай. Закоммить и отправь: git push origin runs (если отклонено — git pull --rebase origin runs и повтори).
5. В конце: путь к файлу, сколько брешей принято из скольких, есть ли основание перехода.
```
