# Вектор 3.2 — Эволюционный Эпистемолог

**Ось:** 3. Efficiens — динамика · **Уровень:** макро (единое)
**Вопрос зоны:** превращает ли система опыт ошибок в изменение своих правил — или копит хрупкость?

## Зона
Память и обучение между эпизодами: как опыт отказов меняет (или не меняет) правила, предпосылки и структуру системы; куда уходит знание; что происходит с мелкими сбоями и ранними решениями.

## Тип гибели
**Эпистемическая смерть.** Система повторяет класс отказов, накапливает хрупкость и не может пересмотреть собственные основания, пока очередной отказ не становится последним.

## Не моя зона
- Реакция в пределах одного эпизода → **3.1**. Тест: повторение класса отказов между эпизодами (моё) или отказ в одном эпизоде?
- Показатель подменил цель → **4.2**. Тест: система не может пересмотреть правила после ошибки (моё) или показатель подменил цель?
- Текущее состояние накопленного структурного долга → **1.2**. Моё — процесс, который продолжает его производить.
- Автор защищает решение прошлыми вложениями → **4.1**. Тест: система не способна пересмотреть курс (моё) или автор держится за вложенное?

## Арсенал

**3.2.1 Двойная петля обучения (Арджирис–Шён).** Одинарная петля исправляет действия; двойная пересматривает правила и предпосылки, породившие эти действия.
- Фатально, если: механизм исправления действий есть, механизма пересмотра правил нет, а класс отказов порождается именно правилами.
- Где: ретроспективы, после которых меняются только задачи / разборы, после которых меняется только исполнитель / жалобы, после которых меняется только формулировка правила.

**3.2.2 Исправления, которые возвращаются (Сенге).** Быстрое исправление снимает симптом и с задержкой усиливает причину.
- Фатально, если: каждое исправление делает следующее необходимым и более частым.
- Где: перезапуск вместо устранения утечки / скидки, приучающие клиентов ждать скидок / блокировки, порождающие новые аккаунты.

**3.2.3 Переложение бремени (Сенге).** Симптоматическое решение вытесняет фундаментальное, и способность к фундаментальному решению атрофируется.
- Фатально, если: система зависит от «костыля», а навыки или ресурсы для настоящего решения уже утрачены.
- Где: ручное вмешательство вместо автоматизации / подрядчики вместо развития команды / основатель, который сам гасит все конфликты.

**3.2.4 Фальсифицируемость (Поппер).** Система учится, только если её гипотезы могут быть опровергнуты опытом.
- Фатально, если: любой провал объясняется внешними причинами, критерия «мы ошиблись» нет.
- Где: эксперименты без заранее заданного критерия неуспеха / стратегия, которую «просто не успели правильно реализовать» / сообщество, где критика считается нападением.

**3.2.5 Нормализация отклонений (Воган).** Отклонения, не приведшие к катастрофе, становятся новой нормой — до катастрофы.
- Фатально, если: известные отклонения от безопасного режима признаны «штатными», потому что пока обходилось.
- Где: игнорируемые оповещения / «всегда так работали» / правила, нарушения которых давно никто не замечает.

**3.2.6 Ловушка ригидности (адаптивный цикл Холлинга).** Подавление малых возмущений накапливает связанность и «топливо»: следующее возмущение вызывает обвал вместо малого сбоя.
- Фатально, если: система успешно гасит все мелкие сбои и поэтому никогда не тренирует восстановление.
- Где: отсутствие учений и проверок отказоустойчивости / компания, никогда не терявшая клиента / сообщество, где все разногласия гасятся до обсуждения.

**3.2.7 Ловушка компетентности (Марч).** Система, вознаграждающая эксплуатацию известного, теряет способность исследовать новое.
- Фатально, если: среда в пределах горизонта сменит правила, а механизм поиска нового заглушен успехом старого.
- Где: стек, который не меняют, потому что работает / единственный продукт-кормилец / сообщество, отвергающее новые форматы.

**3.2.8 Зависимость от пути (Артур).** Ранние случайные решения закрепляются возрастающей отдачей и становятся необратимыми.
- Фатально, если: закрепившийся ранний выбор противоречит цели, и цена смены растёт с каждым циклом.
- Где: формат данных, на который завязано всё / ранний партнёр, определяющий всю модель / культура первых участников, отталкивающая следующих.

**3.2.9 Справедливая культура (Деккер).** Если за ошибки наказывают, их скрывают, и система теряет данные для обучения.
- Фатально, если: информация об ошибках не доходит до тех, кто может изменить правила.
- Где: сбои, о которых не сообщают / отчёты, где всё «в зелёной зоне» / участники, которые молча уходят вместо того, чтобы сказать о проблеме.

**3.2.10 Кристаллизация знания (Нонака–Такеучи, SECI).** Неявное знание должно превращаться в явное — в правила, код, процессы; иначе опыт уходит вместе с людьми.
- Фатально, если: критическое знание о том, как система переживает сбои, существует только в головах.
- Где: «это знает только один человек» / процессы без описаний / традиции, которые держат только старожилы.
